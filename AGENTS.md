## Project Overview

**Query Loop Load More** is a WordPress plugin that extends the Gutenberg Query Loop Pagination block with a "Load More" option. Users can load more posts via a button or infinite scroll without refreshing the page. Published by WordPress.com Special Projects (a8cteam51).

## Conventions

### PHP

- **Namespace**: `WPcomSpecialProjects\Qllm`
- **Prefixes**: All globals/functions MUST use `wpcomsp_` or `wpcomsp_qllm_` (enforced by PHPCS)
- **Text domain**: `query-loop-load-more` for all `__()`, `esc_html__()`, etc.
- **Coding standards**: WordPress Coding Standards via `.phpcs.xml` (extends Team51 configs)

### JavaScript / React

- Uses `@wordpress/*` packages (block-editor, components, hooks, i18n, etc.)
- **Text domain for `__()`**: MUST be `query-loop-load-more` (the editor currently uses `wp-load-more` in some places—this is a known inconsistency; prefer `query-loop-load-more` for new code)
- Block filter namespace: `wp-load-more/custom-controls`

### CSS / SCSS

- Uses `wp-load-more__button`, `wp-load-more__infinite-scroll`, `qllm-loading`, `qllm-load-more` class names
- Styles are in `assets/css/src/` and imported by `index.js` and `style.scss`

### Git & Branches

- Branch naming: `fix/...`, `feature/...`, or `update/...` as needed
- Commit messages: Descriptive; reference issues when relevant
- Do NOT commit `vendor/`, `node_modules/`, or `assets/js/build/` (build output is committed for distribution; verify `.gitignore` and `.distignore`)

## Architectural Decisions

1. **No custom block**: The plugin extends `core/query-pagination` via `register_block_type_args` (filter) and a custom `render_callback`. It does NOT register a new block type.

2. **Region-based matching**: Multiple Query Loops on a page are disambiguated via `data-qllm-query-region` on `.wp-block-post-template`. The frontend matches fetched HTML by this attribute to append posts to the correct container.

3. **Fetch-based loading**: Posts are loaded via `fetch()` of the paginated URL; HTML is parsed and the matching post template region is extracted and appended. No REST API; uses the same server-rendered HTML as normal pagination.

4. **Inherit query**: When the block uses "Inherit query from template", the plugin uses `$wp_query` and the `paged` parameter instead of query-block-specific vars.

5. **Singleton Plugin**: `Plugin::get_instance()` is the single entry point; bootstrap lives in `functions.php` and `query-loop-load-more.php`.

## Common Pitfalls

1. **CRITICAL – Never edit WordPress core**: Modify only plugin files. Do not patch `wp-includes/` or `wp-admin/`.

2. **Build before testing**: If "Load More" or editor controls don’t work, ensure `npm run build` has been run and `assets/js/build/` contains fresh output.

3. **Text domain inconsistencies**:
   - PHP: Use `query-loop-load-more` everywhere.
   - `functions-bootstrap.php` uses `a8csp-scaffold` in error messages (legacy); consider fixing to `query-loop-load-more`.
   - Editor JS in `index.js` uses `wp-load-more`; PHPCS expects `query-loop-load-more`. When adding new strings, use `query-loop-load-more`.

4. **Block vs pagination**: The plugin enhances `core/query-pagination`, not `core/query`. Changes to Query Loop block behavior should go through the pagination block’s attributes and render callback.

5. **No `blocks/` directory**: `package.json` references `build:blocks` and `blocks/src`, but this project has no custom blocks. The real build output comes from `build:assets:scripts` → `assets/js/build/`.

6. **Asset meta**: `includes/assets.php` provides `wpcomsp_qllm_get_asset_meta()`. It reads `.asset.php` files next to built JS to get dependencies and version. Do not remove or rename these generated `.asset.php` files.

## Deployment

- **GitHub Release**: Triggered on `release` (released). Runs `composer install --no-dev`, `npm ci`, `npm run build`, then zips the project (excluding dev files) and attaches to the release.
- **WordPress.org SVN**: Manual via `push-deploy` workflow. Requires `SVN_USERNAME` and `SVN_PASSWORD` secrets. Uses `10up/action-wordpress-plugin-deploy`.
- **Readme/Assets**: `wp-readme-assets-update` pushes readme and assets to WordPress.org trunk (manual workflow).
